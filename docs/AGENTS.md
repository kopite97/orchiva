# 문서 규칙

- 현재 MVP 요구사항은 [MVP 설계](design/mvp-design.md), 후속 데스크톱 방향의 사용자 합의와 인계는 [데스크톱 전환 방향과 개발 인계](design/desktop-handoff.md), 검증된 PoC 사실은 [PoC 결과](decisions/poc-results.md), 상세 구현 순서와 진행 상태는 [계획 목록](plans/README.md)에서 관리한다.
- 문서는 아래 역할별 디렉터리에 둔다. 이 `AGENTS.md`는 `docs/` 전체에 적용되는 지침 진입점이므로 현재 위치에 유지한다.
- 필요한 아키텍처 결정은 한 주제의 맥락·결정·근거·영향을 기록하고 기존 결정을 대체할 때 이력을 보존한다.
- 현재 구현, 향후 설계, 실제 검증, 모의 검증을 명확히 구분한다. 역사적 PoC 결과를 현재 코드에 맞춰 소급 변경하지 않는다.
- 한 문서에 원본을 두고 다른 문서에서는 상대 링크로 연결한다. 새 문서 파일명은 소문자 kebab-case를 사용하며 `AGENTS.md`, `README.md`는 관례를 따른다.
- 날짜와 검증 환경을 명시한다. 새 기계에서 재현할 절차와 기존 로컬 데이터가 있어야 가능한 절차를 구분한다.
- 문서만 변경했으면 링크·내용·인코딩 검증을 수행한다. 소스 테스트를 실행하지 않은 경우 문서 검증과 혼동하지 않는다.

## 역할별 문서 위치

| 디렉터리 | 역할 |
| --- | --- |
| `design/` | 제품 설계, 후속 개발 방향과 개발 인계 |
| `guides/` | 설치·실행·사용 안내와 문제 해결 |
| `agents/` | 공통 작업 절차, 저장소·소스·검증 지침 |
| `plans/` | 구현 계획, 계획 목록·템플릿, 단계별 실행 기록 |
| `decisions/` | PoC·M0~M6의 검증 결과, 기술 결정과 확인된 제약 |
| `evidence/` | 검증 결과 JSON, 화면 등 증거 자료 |

같은 역할의 문서는 해당 디렉터리에 함께 둔다. 문서를 이동할 때 들어오는 링크와 문서 내부의 상대 경로, 스크립트 참조를 함께 갱신하며 과거 검증 사실과 증거 내용은 유지한다.
