# 프로젝트 규칙

## 소스와 실행 대상

| 위치 | 역할 |
| --- | --- |
| 이 저장소 `orchiva-plugin` | 사용자가 지정한 기본 소스 폴더. Plugin 코드, 하네스, 설계와 구현 계획 |
| `https://github.com/kopite97/orchiva.git` | Orchiva 소스 원격 저장소 |
| `../orchiva-PoC` | 실제 연동 작업을 수행하는 sandbox 저장소. 현재 설정의 허용 remote는 `kopite97/PoC-sandbox` |
| `%USERPROFILE%\.orchiva` | 프로젝트 설정과 요청·결과의 영속 데이터 |
| `%USERPROFILE%\.paseo-orchiva` | 독립 daemon의 데이터·로그·sandbox Worktree |

소스의 원격 연결과 제품이 작업할 대상 저장소 설정은 별개다. Orchiva 소스 원격을 등록했다는 이유로 `project.json`, sandbox 경로 검사, 허용 remote를 바꾸지 않는다. RNG 등 운영 저장소는 실제 연동 시험 대상에서 제외한다.

## Git과 변경 관리

- 새 개발 브랜치는 기본적으로 `codex/` 접두사를 사용한다. 기존 사용자 변경은 보존하고 목적과 무관한 초기화·되돌리기·파일 이동을 하지 않는다.
- 최초 구현 전에 복원 가능한 기준점을 확보한다. 초기 커밋이 없으면 사용자에게 허용된 범위에서 로컬 기준 커밋 또는 검토한 소스 백업을 마련하고 위치·식별자를 기록한다. 원격 저장소가 있다는 사실만으로 백업이 존재한다고 간주하지 않는다.
- 실제 연동 에이전트에는 sandbox 제한과 push·merge 금지 규칙을 전달한다. 개발자의 소스 관리와 제품이 수행하는 Git 작업을 혼동하지 않는다.
- 자격 증명, `.env`, 로컬 인증 파일, 요청 원본 데이터 전체, `node_modules`를 커밋하지 않는다. 설정 예제가 필요하면 비밀값 없는 예제를 작성한다.

## 환경과 파일

- 버전은 현재 lockfile과 설치된 SDK를 기준으로 확인한다. M0의 API 제약을 추측으로 해결하거나 `node_modules`를 직접 고치지 않는다. 의존성 변경 시 manifest와 lockfile을 함께 갱신하고 이유를 기록한다.
- 실행 문제를 해결하려고 사용자 전역 환경 변수, Codex 사용자 설정, sandbox·승인 정책을 임의 변경하지 않는다. 기존 `start-paseo.ps1`의 자식 프로세스 환경 조정 범위를 유지한다.
- 인증값은 필요한 연결 코드에서만 읽고 출력·문서·검증 로그에 포함하지 않는다. 상태 진단에는 값 대신 파일 존재·접속 성공 여부를 기록한다.
- Windows 명령은 명확한 작업 디렉터리와 인수로 실행한다. 삭제·이동이 필요하면 대상 절대 경로와 소유 범위를 먼저 확인한다. 다른 작업의 파일을 정리하지 않는다.

## 증거와 임시 산출물

- PoC 요청 JSON, PLAN 원본, 검사 파일·해시, 실패 로그, 결과·판정 이력은 보존 대상이다. 고정된 기존 PoC 키를 새 시험에 재사용하지 않는다.
- 새 시험은 구분 가능한 실행 ID를 사용한다. 검토용 출력은 시스템 임시 디렉터리의 작업별 폴더에 두고, 재현에 필요한 결과는 비밀값을 제거하여 계획의 검증 기록 또는 명시한 증거 파일에 보존한다.
- 일반 임시 로그는 필요한 결과를 기록한 후 이번 작업 소유분만 정리한다. 원본 장애 증거가 아직 필요하면 보존 이유와 위치를 기록한다. `.gitignore`를 삭제 지시로 해석하지 않는다.
- 새 `AGENTS.md`가 기존 Worktree나 과거 기준 커밋으로 만든 Worktree에 자동 반영된다고 가정하지 않는다. 실행 에이전트가 필요한 sandbox 제약은 작업 프롬프트·로컬 PLAN에서도 전달하고 확인한다.

## 지침 유지

루트 `AGENTS.md`는 진입점으로 작게 유지한다. 작업 절차는 `docs/agents`, 제품 설계와 후속 방향은 `docs/design`, 단계별 구현과 실행 기록은 `docs/plans`에 둔다. 전체 문서의 역할별 위치는 [문서 규칙](../AGENTS.md)을 따른다. 같은 규칙을 여러 문서에 복사하지 말고 원본을 연결한다.
