# 소스 규칙

## 계층과 의존성

| 위치 | 책임과 경계 |
| --- | --- |
| `client/` | 입력·진행·검토 UI. 파일·프로세스·저장소 직접 접근과 완료 판정 정책을 두지 않는다. |
| `shared/contracts/` | Zod 입력·응답·영속 스키마와 RPC 계약. 클라이언트와 서버가 같은 정의를 사용한다. |
| `server/domain/` | 요청·계획·상태 규칙. Paseo, 파일 시스템, 프로세스 API에 의존하지 않는다. |
| `server/application/` | 유스케이스, 순서·잠금·판정·복구. 외부 효과는 포트로 호출한다. |
| `server/adapters/` | Paseo, JSON 저장, 파일 증거, 검증 프로세스. 외부 예외를 의미 있는 결과로 변환한다. |
| `index.server.ts`, `index.client.tsx` | 구성과 등록. 큰 상태 처리 로직을 추가하지 않는다. |
| `scripts/` | 재현 가능한 운영·검증 진입점. 제품 정책을 별도 구현해 우회하지 않는다. |

현재 TypeScript ESM, React Native, Zod 구조를 따른다. 실제 필요 없는 범용 프레임워크나 다른 언어·UI 프레임워크를 추가하지 않는다. SDK의 private 구현에 의존해야 하는 상황이면 먼저 제약을 기록하고 공개 API 경로를 검토한다.

## 실행과 상태

- 세션 생성, 실행 종료, 자동 검증 통과, 사용자 완료 판정은 서로 다른 사건이다. 상태 전이와 허용 행동은 서버에서 검증한다.
- 연결 실패는 관측 오류로 취급한다. 관측 불가를 실행 실패나 성공으로 추정하지 않는다. 종료·중단 사유가 확인된 경우에만 해당 상태를 기록한다.
- 같은 명령 키의 재호출은 동일 작업을 가리켜야 한다. 같은 키에 다른 입력은 거부한다. 복구 시 요청·TASK·Worktree·세션의 정체성을 유지한다.
- 외부 효과 전 실행 의도를 저장하고 응답이 불확실하면 대조한다. 최근 이력에 없다는 이유만으로 재전송하지 않는다.
- 조회가 새 실행·새 시도·무조건적인 재검증을 발생시키지 않는 방향으로 확장한다. 현재 PoC 조회의 부수 효과는 검증과 마이그레이션에서 고려한다.
- 동시성 확대는 하지 않는다. MVP의 실행 슬롯과 잠금 순서는 [설계](../design/mvp-design.md)를 따른다.

## 결과와 저장

- 완료 판정에는 해당 결과 ID, 실행 정보, 파일 지문, 판정 근거를 결합한다. 오래된 결과·변경된 파일을 승인하지 않는다.
- 이전 실패 증거와 판정을 새 시도·재검증이 덮어쓰지 않도록 한다. 기존 형식에서 구현되지 않은 이력은 있었다고 꾸미지 않는다.
- 스키마 변경에는 읽기 호환성, 마이그레이션, 원본 보존, 실패 처리와 테스트를 함께 설계한다. 원자적 파일 교체와 다중 파일 트랜잭션을 같은 것으로 보지 않는다.
- 파일 경로는 정규화·실경로 검증으로 허용 루트 소속을 확인한다. 파일 증거에 미추적·삭제·검사 입력을 어떻게 포함하는지 명시한다.
- 외부 프로세스는 shell 문자열 조합보다 실행 파일·인수 배열을 사용한다. 시간·출력·파일 수 한도를 적용하고 초과·생략을 통과로 처리하지 않는다.

## UI와 비동기 수명

- 질문 대기, 전송 확인 대기, 코드 실패, 검증기 오류에 맞는 행동을 보여준다. 일반 오류 하나로 합치지 않는다.
- 사용자 메모와 입력을 통신 실패 때문에 지우지 않는다. 새 결과가 도착하면 기존 확인 상태를 재사용하지 않는다.
- compact·넓은 화면에서 상태, 주요 행동, 오류를 읽고 조작할 수 있게 한다. 접근성 이름과 비활성 사유를 제공한다.
- 연결·타이머·구독의 소유자와 종료 절차를 정한다. 중복 루프·겹친 주기 실행·해제 후 상태 쓰기를 막는다. 종료 함수가 여러 번 호출되어도 안전해야 한다.
