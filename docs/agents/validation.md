# 검증 기준

## 변경별 선택

| 변경 | 필요한 검증 |
| --- | --- |
| 지침·설계·계획만 변경 | 참조 파일·상대 링크, 지침 적용 범위, 상태·템플릿 일치, 실제 명령 존재, diff·인코딩 확인. 런타임 검사는 불필요 |
| 계약·도메인·애플리케이션 | 타입 검사, 관련 동작 테스트, 기존 회귀 테스트. 상태·중복·실패 경계의 의미 있는 시나리오 포함 |
| 저장·마이그레이션 | 타입 검사·테스트와 원본 보존, 중단, 손상 파일, 미래 버전, 저장 중복의 경계 확인 |
| Paseo·프로세스·시작 스크립트 | 타입 검사·관련 테스트 및 변경한 경로의 실제 연동. Windows 경로·연결·종료 확인 |
| UI | 타입 검사·영향 있는 테스트, 실제 화면에서 해당 사용자 흐름·오류·빈 상태, compact와 넓은 화면 확인 |
| 릴리스 수준 통합 | 승인된 단계의 수용 기준과 기존 PoC 회귀. 성공·실패·복구·재시작을 구분하여 보고 |

작은 변경에 구현을 그대로 반복하는 테스트를 추가하지 않는다. 필요한 검사 통과 후에는 새 변경이나 미해결 문제가 없는 한 같은 검사를 반복하지 않는다.

## 현재 사용할 수 있는 명령

아래 명령은 소스 루트 `orchiva-plugin`에서 실행한다. 당시의 `package.json`을 확인하고, 새 명령은 구현되기 전까지 존재한다고 안내하지 않는다.

| 명령 | 조건과 의미 |
| --- | --- |
| `npm run typecheck` | TypeScript 정적 검사 |
| `npm test` | 현재 `server/tests/*.test.ts` 테스트. 최신 통과 수는 실행 결과로 기록 |
| `npm run m0 -- help` | 명시적 M0 시험 단계 안내. 실제 연동은 실행 ID와 보존 manifest 필요. [결과·재검증](../decisions/m0-runtime-foundation.md) 참조 |
| `npm run m1 -- help` | v1 원본 백업과 v2 실제 대조. 기존 실행 재검증은 [M1 결과](../decisions/m1-storage-state.md) 참조 |
| `npm run verify` | 기존 초기 PoC 두 요청의 PLAN·Worktree·파일·재호출 검사. 기존 데이터와 daemon 필요 |
| `npm run verify:lifecycle` | 기존 생명주기 두 요청의 판정·복구 증거·재호출과 원래 테스트 재실행. 기존 데이터와 daemon 필요 |
| `.\scripts\start-paseo.ps1` | 독립 daemon 시작. 상태와 작업 범위를 먼저 확인 |
| `.\scripts\start-paseo.ps1 -Restart` | daemon 재시작. 일반 회귀는 활성 작업이 없을 때, 장애 시험은 시험 소유 작업만 있을 때 수행 |

M1 이후 목록 조회는 외부 관측·검증을 수행하지 않는다. 저장소 첫 로드 시 v1 마이그레이션은 원본 백업 후 수행된다. `verify` 계열은 새 세션을 만들지 않지만 생명주기 검사는 원래 검사 파일을 실행하고 기존 명령을 재호출하므로 명령별 부수 효과를 확인한다. `smoke`, `lifecycle -- start`, `recover`, `approve`는 생성·재개·판정 동작을 포함한다. 기존 완료 기록을 새 시험의 재료로 변경하지 않는다.

## 실제 연동과 장애 시험

- 적용할 계획의 승인 범위, 시험 소유 실행 ID, 허용 sandbox, 프로세스·포트·daemon home을 먼저 확인한다. 무관한 활성 작업이 있으면 중단하지 않고 가능한 정적·모의 검증을 먼저 진행한다.
- 프로세스 종료·연결 차단은 새 시험에 소유권이 확인된 대상에만 주입한다. 종료 후 정상 상태 복원 절차와 남길 증거를 계획에 둔다.
- 중복 방지는 최종 ID뿐 아니라 해당 실행의 Worktree·세션·메시지 수로 확인한다. 응답 유실 위치와 재시작 여부를 기록한다.
- 검증 종류를 `정적`, `모의`, `실제 연동`, `GUI`로 구분한다. 장애를 모의로만 확인했으면 실제 장애 복구를 검증했다고 표현하지 않는다.
- 합격·불합격·미실행·환경 차단을 구분한다. 명령 성공만으로 자연어 완료 조건을 모두 충족했다고 판정하지 않는다.

## 기록 형식

계획의 검증 표에는 날짜, 변경 기준점, 명령 또는 절차, 검증 종류, 기대 결과, 실제 결과, 증거 위치와 남은 문제를 남긴다. 로그에는 인증값을 포함하지 않는다. 원본 장애 증거와 임시 산출물의 보존 규칙은 [프로젝트 규칙](repository-guidelines.md)을 따른다.
