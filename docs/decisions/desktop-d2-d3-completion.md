작성일: 2026-11-16 · Asia/Seoul. ROOT: `C:/Users/USER/lib/orchiva-plugin`. 기준: `b08dc13` 이후 `codex/desktop-d1-foundation`의 로컬 변경. 사용자 지시: D3까지 진행하되 컴퓨터 유스는 사용하지 않는다.

상태: **D2·D3 구현 및 비GUI 검증 완료, 화면 수용 검증 대기**. [전환 PLAN](../plans/desktop-transition.md)은 D4~D6와 GUI가 남아 `active`다. 실행부·모델 호출은 새 격리 fixture와 PoC sandbox의 별도 clone/Worktree에서만 수행했다. Orchiva 소스의 개발 지침 파일은 사용자 프로젝트 초기화 규칙으로 개명하지 않았다.

## 구현한 흐름

- WinUI 작업실에서 프로젝트 등록 → 초기화 변경 미리보기/확인 → 소스와 분리한 결과물 폴더 설정 → 실제 지침 조회·편집 → 기획/코딩 새 요청 또는 수정 요청 → AI PLAN 확인 → 실행 → 자동 확인·품질 검토 → 결과물 내보내기 → 파일 선택 반영/되돌리기를 제공한다.
- 프로젝트 등록 자체는 소스에 쓰지 않는다. 명시적 초기화가 루트 `AGENTS.md`, `docs/agents/workflow.md`, `docs/plans/plans.md`와 목록, `docs/decisions/decisions.md`, `docs/evidence/evidence.md`를 만든다. 하위 AGENTS는 같은 디렉터리의 명시적 지침으로 이관하고 충돌 시 중단한다. 기존 지침·상대 링크·적용 범위·백업을 보존한다. `docs.md`는 만들지 않는다.
- 실제 파일이 권위 원본이다. `docs/.orchiva/project.json`, `requests/<token>.json`의 v3 envelope, 입력 snapshot, 초기화/반영 journal과 백업을 프로젝트에 둔다. 읽을 PLAN은 `docs/plans/plan-<token>.md`, 검증은 `docs/evidence/plan-<token>/<resultId>/`, 검토 결정은 `docs/decisions/plan-<token>-<reviewId>.md`다. 앱 registry는 프로젝트 ID와 경로 연결을 보관한다. 로컬 계획 작성용 실행 디렉터리는 재현용 사본이며 원본을 대신하지 않는다.
- 지침 검사 공통 명령은 `npm run project:instructions -- <sourceRoot> [--content]`다. 앱과 같은 검사기를 사용해 필수 파일, 내용 해시, 루트 지도 링크, 누락과 경로 이탈을 확인한다.
- 모델과 수준은 실제 Paseo provider 목록에서 읽는다. 파일 이름·검사 코드 입력을 요구하지 않는다. 자동 확인 profile은 파일 근거 또는 기존 Node 테스트 탐색이다. AI가 제안한 임의 shell 명령을 자동 검증기로 실행하지 않는다. 최종 검토는 실제 결과 지문, 자동 검사, 품질/검사 변경 확인 선택을 결합한다. 기존 v2의 10자 메모 판정을 가짜 메모로 우회하지 않는다.

## 발견한 문제와 보완

1. run 007 첫 시작은 45초 준비 한도에서 끝났다. 해당 생성 프로세스만 정리했고 같은 설정의 재시작이 준비 완료됐다. 제한을 늘리거나 전역 설정을 변경해 숨기지 않았다.
2. v3 저장 후 명령 배열을 교체하면서 실행부가 보관하던 checkpoint 참조가 끊겼다. 저장 갱신 필드를 기존 v2 저장소와 맞추고 회귀 테스트를 추가했다. 이미 생성된 run 007 Worktree/Agent를 대조해 재사용했으며 새 리소스를 만들지 않았다.
3. 제작 모드를 생략하면 이 PC의 사용자 기본 읽기 전용 설정을 상속했다. 새 제작에 `auto`를 명시했고 run 008의 최초 실행 통과로 확인했다. run 007의 시험 소유 세션만 공개 API로 모드를 맞춘 뒤 같은 세션을 재개했다.
4. 내보내기·적용의 부분 실패는 단일 파일 원자 교체만으로 해결되지 않는다. 대상 경로 고정, 사전 intent, 파일별 hash/백업, 동일 명령 재시도와 부분 되돌리기를 추가했다. UI에는 반영 이력과 미완료 작업 이어서 처리를 연결했다.
