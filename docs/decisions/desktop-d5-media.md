# D5 임시 미디어 제작과 검증

검증일: 2026-11-16~17 · Asia/Seoul. 변경 기준 `e0248d9`(D4까지 main 반영). 사용자가 D5 구현을 지시했고 생성 도구에 대해 “생성도구는 따로 없어. 일단 임시로 아무거나 적용해줘”라고 답했다. 이 기록은 임시 생성기를 사용하는 D5 범위이며 외부 생성 모델이나 D6 배포 완료를 뜻하지 않는다.

## 구현 계약

`orchiva-procedural-v1`은 계정·API 키·네트워크 없이 명시적 숫자 규격으로 실제 바이너리를 만든다. 아트는 RGBA8 PNG 도형, 사운드는 PCM16 WAV 합성 단음, 효과는 확산 링 가로 PNG 시트와 재생 규격 JSON이다. WinUI 기본 프리셋은 투명 원형, 44.1kHz 모노 사인파/10ms 페이드, 확산 링이다. 원형은 직사각형 캔버스에서도 비율을 유지한다.

자유 문장의 화풍·음악·Unity 네이티브 파티클을 해석해 생성하는 모델은 없다. UI·PLAN·Agent 프롬프트에 한계를 표시한다. 기존 Codex 모델은 읽기 전용 PLAN 작성과 생성 자산의 검사·보고를 담당하며 이미 생성한 자산을 변경하지 않도록 지시한다. 숫자 규격을 바꾸려면 새 요청 또는 부모 결과를 참조하는 수정 요청을 사용한다. 임의의 원본 이미지/음원을 편집하는 기능은 아니다.

제작은 기존 v3의 입력 snapshot → PLAN 확인 → 실행 intent → Worktree → 생성 → Agent → 독립 검사 → 사용자 검토 순서다. `media/<token>/`에만 생성하며 원본 소스는 선택 반영 전까지 쓰지 않는다. 같은 실행의 준비 재호출은 동일 바이트만 허용한다. 형식 검사와 결정적 생성 결과의 SHA-256을 대조해 Agent·외부 편집이 자산을 바꾸면 실패로 남긴다. 기존 v2·기획/코딩 계약은 유지한다.

미리보기 RPC는 현재 결과 ID, Worktree 소유권, 파일 지문, 명시한 자산 경로와 해시를 확인하고 128KiB 청크를 반환한다. C#에서도 크기·해시를 확인한 뒤 WinUI PNG 디코더 또는 WAV 플레이어에 메모리 스트림을 전달한다. 결과 변경·요청 전환·화면 이탈 시 미리보기를 비운다. 효과는 가로 프레임 시트를 보여주며 애니메이션 재생이 아님을 표시한다.

## 예산과 미지원 범위

| 경계 | 현재 계약 |
| --- | --- |
| 명시적 미디어 수집 | 파일당 32MiB, 전체 128MiB, 100개; 64KiB 스트리밍 해시. 현재 생성기는 1~2개 파일만 생성 |
| 이미지 생성/디코딩 | 전체 16Mi 픽셀. PNG 검사기는 RGBA8·비인터레이스·필터 0·IHDR/IDAT/IEND만 지원 |
| WAV | PCM16, 22.05/44.1/48kHz, 1~2채널, 최대 30초; 주파수는 Nyquist 미만. UI는 44.1kHz 모노·최대 10초 |
| 내보내기·반영 journal | 직렬화된 JSON 24MiB. base64 때문에 원시 자산 허용량과 다르며 초과 시 내보내기를 거부하고 결과 보존 |
| 기존 소스 입력 snapshot | 기존 파일당 2MiB/합계 16MiB 유지. 큰 원본 미디어 프로젝트의 입력/수정 지원을 주장하지 않음 |
| 기존 evidence | 기존 2MiB/300개 유지. 큰 파일 허용은 생성 계약에 명시한 미디어 경로에 한정 |

ignored 파일도 명시된 생성 경로이면 수집한다. 경로 이탈·중복 대소문자·내부 메타데이터·symlink·누락·한도 초과는 성공으로 처리하지 않는다. 외부 포맷 변환, Aseprite/Unity 연결, 임의 모델/플러그인 선택, 일반 이미지 디코더, 효과 실시간 재생은 구현하지 않았다. 음질의 주관적 청취 평가는 자동 규격 검사와 구분한다.

아트 001의 외관 결함과 실패 기록은 삭제하지 않았다. 원형 비율 회귀 검사를 추가하고 002로 검증했다. PLAN 본문이 요청별 하위 경로를 생략하는 문제는 최종 생성 계약으로 실행 범위를 고정했고, 후속 PLAN 프롬프트에도 실제 token 경로를 전달하도록 보완했다. 생성 계약 재동기화는 전용 주석 경계만 교체해 외부 추가 문장을 보존한다. 최신 보완 뒤 관련 Node 11/11·타입 검사와 재시작 C# 검사를 통과했다. 새 초안의 이전 경로·반영 표시 초기화는 최종 빌드에서 확인했으며 그 표시 수정 뒤 GUI를 다시 실행한 것은 아니다.

첫 추가 테스트의 예상 오류 문자열은 `SIZE_LIMIT`이 아니라 기존 `FILE_LIMIT`이어서 기대값을 고쳤다. 직접 Node strip-types 호출은 확장자 없는 import를 해결하지 못했으므로 프로젝트의 `tsx` 테스트 명령을 사용했다.

## 재현과 보존

새 실행은 `node --import tsx scripts/desktop-foundation.mjs prepare d1-d5-<새 ID> --empty`로 준비한다. 생성된 `desktop.json`의 `paseoCliPath`를 설치된 CLI로 지정하고 `scripts/start-desktop-runtime.ps1 -Config <desktop.json>`로 시작한 뒤 D5 하네스를 실행한다. 하네스는 신규 manifest를 `wx`로 만들며 같은 ID를 덮어쓰지 않는다. 운영 프로젝트 대신 `orchiva-PoC`를 격리 clone해 사용한다.

이 PC의 runtime은 `.desktop-local/tools/dotnet`, Paseo 0.15.4는 `.desktop-local/tools/paseo`에 있다. GUI 실행 자식에 `DOTNET_ROOT`/`DOTNET_ROOT_X64`와 `ORCHIVA_DESKTOP_CONFIG`를 지정한다. C# 실제 검사는 같은 설정 경로를 `ORCHIVA_D5_CONFIG`로 지정한다. 기존 활성 Aseprite·Unity 프로젝트는 조작하지 않았다.

원본 PLAN·요청·실패/복구·Agent 응답·export·backup은 `.desktop-local/d1-d5-20261116-001`과 `.desktop-local/d1-d5-20261117-002`에 보존한다. 인증값과 원문 전체는 공유하지 않는다. 공유 근거는 [D5 증거](../evidence/desktop-transition/d5-20261117/summary.json)와 그 폴더의 GUI 화면이다. 시험 소유 앱·daemon은 종료했고 기존 사용자 요청 및 격리 legacy 요청 해시는 착수 전과 같다. 임시 생성기 범위의 D5를 완료했으며 D6는 미착수다. 현재 변경은 로컬이며 D5 commit/push는 수행하지 않았다.
