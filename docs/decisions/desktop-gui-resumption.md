복원 중에도 상태 배너 제목이 ‘연결됨’으로 보이던 경로를 수정했다. 파일 반영 충돌 뒤에는 서버의 요청 버전이 바뀌므로 파일 비교를 다시 열 때 최신 요청을 함께 읽도록 수정했다. 첫 실행의 `REVISION_CONFLICT`와 수정 후 재검증은 실행 근거에 함께 기록했다. 초기 Polish 시험 홈의 실행부 시작 시간 초과는 그 홈에서 원인을 확정하지 못했다. GUI 시험 홈에서는 시작·재연결을 확인했다.

## 재현

수정 후 새 홈 `d1-gui-repeat-20261126-001`에서 프로젝트 등록부터 수정 요청 중단까지 연속 21개 단언이 통과했다. 같은 제작 세션의 검사 결과는 통과 → 실패 → 통과였고 수정 요청은 마지막 결과 ID를 부모로 기록했다. TypeScript 검사, Node 129개, 실제 이력이 있는 홈에서 C# 13개(건너뜀 0), WinUI 모의 19개가 통과했다. 제품 앱과 WinUI 시험 앱 모두 경고·오류 0건으로 빌드됐다.

- [WinUI 시험 프로젝트](../../desktop/Orchiva.Desktop.UiTests/Orchiva.Desktop.UiTests.csproj)를 `dotnet build desktop/Orchiva.Desktop.UiTests/Orchiva.Desktop.UiTests.csproj -p:Platform=x64 -p:RestoreLockedMode=true`로 빌드한다. 시험 실행 파일은 해당 프로젝트의 `bin/x64/Debug/net10.0-windows10.0.26100.0/win-x64/Orchiva.Desktop.UiTests.exe`다.
- 시나리오마다 `ORCHIVA_DESKTOP_CONFIG`는 해당 홈의 `desktop.json` 절대 경로, `ORCHIVA_UI_EVIDENCE`는 증거 디렉터리, `ORCHIVA_D123_UI`는 시나리오 이름으로 설정한다. 실행 파일 종료 후 해당 이름의 JSON에서 `passed`와 `checks`를 확인한다.
- 이력 시험은 새 `d1-gui-…` ID로 `npm run desktop:verify -- prepare <ID>`를 실행한다. 실행부를 꺼 둔 상태에서 `history-1`, 이어서 같은 홈에서 `history-2`, `history-3`, `history-4`를 차례로 기동한다. `restore`는 별도 새 홈에 `prepare <ID> --empty`를 사용하며 처음에 실행부가 꺼져 있어야 한다.
- 제작 시험은 새 빈 홈을 준비하고 `node --import tsx desktop/Orchiva.Desktop.UiTests/fixture.mjs seed <ID>`, `npm run desktop:verify -- start <ID>`를 실행한 뒤 `work`를 기동한다. 실제 Codex 로그인과 시험 모델 `codex/gpt-6.1-sol`이 필요하다. `faults`는 같은 홈에서 응답 유실·포커스를 검사한다. `permission`은 해당 홈에서 중단한 수정 요청의 에이전트에 Paseo SDK로 `plan_mode`를 켠 뒤 실행한다. 이 시험은 도착한 질문을 거부하며 종료 후 해당 에이전트 설정을 복원한다.
- 부분 반영은 완료된 주 요청의 두 파일을 undo한 상태에서 `node --import tsx desktop/Orchiva.Desktop.UiTests/fixture.mjs interrupt <ID> <token> <resultId>`로 주입한다. 같은 홈에서 `partial`을 실행한다. 시험 후 `npm run desktop:verify -- stop <ID>`로 해당 홈의 실행부를 종료한다.

컴퓨터 화면을 직접 조작하거나 시스템 배율을 변경하는 시험은 사용자 요청으로 보류했다. [기존 UI-A 시각 검증](desktop-ui-alignment.md)과 [데스크톱 전환 PLAN](../plans/desktop-transition.md)에 이어서 기록한다.
