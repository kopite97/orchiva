## 계약과 판정 규칙

v2 저장 형식은 유지하고 결과의 `files`, `testChanges`, `truncation`, 검사의 `checkId/status/failureKind/inputFingerprint/truncated`, 판정의 `criteriaReviews/testChangesAcknowledged/testChangeNote`를 선택적 필드로 확장했다. 기존 결과는 재저장하거나 누락 정보를 추정하지 않는다. 새 결과부터 실제 수집한 값이 들어간다.

새 판정은 명령 키·예상 revision·최신 resultId가 필요하다. 모든 조건을 중복 없이 제출하고 각 참조가 해당 결과에 실제로 존재해야 한다. 검사·파일 참조가 없으면 10자 이상의 수동 확인 내용이 필요하다. 자동 검사 0건이면 파일 참조 여부와 무관하게 조건별 수동 근거가 필요하다. 승인에는 모든 조건 충족과 검사 정상 통과, 실행/검증 실패 없음이 추가로 필요하다. 수동 문장의 진실성이나 의미를 자동 인증하지 않는다.

판정 직전 외부 세션이 종료되어 있는지, sourceKey가 동일한지, 파일 지문이 동일한지 확인한다. 미확정 명령·오래된 revision·결과·지문은 거부한다. 파일이 바뀌어도 최신 결과를 null로 지우거나 자동 재검증하지 않는다. 오류 안내 후 사용자가 **검증 다시 실행**을 누르면 같은 시도에 새 결과를 추가한다. 기존 M1의 지문 불일치 시 자동 검증 전이 테스트 2건을 이 명시적 재검증 정책에 맞게 갱신했다.

같은 판정 명령 재호출은 원래 payload를 비교해 중복 쓰기를 막는다. 이전 PoC의 이미 저장된 판정 재호출은 호환하지만, 이전 입력 형식으로 새 판정을 우회할 수 없다. 수정 요청도 조건별 근거와 최종 사유를 보존하고, 사유를 재개 입력에 남긴다. 실제 재개는 별도 명시적 행동이다.

## 근거 수집과 과거 조회

지문에는 HEAD, 변경·미추적 파일, 등록한 검사 입력의 경로·해시·크기·삭제 여부가 들어간다. 변경되지 않은 tracked 검사 파일도 포함한다. Git의 NUL 구분 경로를 trim하지 않아 앞에 공백이 있는 파일도 수집한다. 검사 입력의 ignored 상태는 worktree 밖의 `.git/info/exclude`·전역 ignore로 바뀔 수 있으므로 이 상태도 지문에 반영한다. ignored 산출물 자체는 지원하지 않으며 ignored 검사는 오류다.

검사 상태는 `passed`, `failed`, `error`, `skipped`다. assertion/문자열 불일치, 검증기 실행 오류·시간 제한, 전체 예산 소진으로 시작하지 않은 검사를 구분한다. 파일당 2 MiB·전체 300개 한도 초과는 수집 실패로 남는다. 전체 검사 예산 20초, Node 검사당 최대 10초와 읽기 권한 제한은 유지한다. 수집 전후 지문이 다르면 해당 결과를 실패 처리한다.

로그는 마지막 16,000자, 최종 응답은 마지막 32,000자, diff 요약은 앞 16,000자를 보존하고 잘림 표시를 남긴다. Node 프로세스 출력 버퍼 한도 초과는 검증 오류다. 파일 크기/개수 한도 초과는 출력 잘림과 다르게 표시한다. 수집 자체를 완료하지 못한 경우에는 새 부분 결과를 만들지 않고 기존 `record.error`로 수집 실패를 표시한다.

검사 입력의 최초 수집 해시를 기준으로 이후 결과의 실제 해시를 비교한다. 변경되면 승인에 변경 확인과 10자 이상의 사유가 필요하다. 검사 파일 최초 생성 또는 테스트 자체의 타당성을 자동 인증하는 기능은 아니다. 과거 데이터에 없는 최초 해시는 새로 수집한 시점부터 기준을 만든다.

`request.inspect-result`는 선택한 결과와 현재 파일 지문을 명시적으로 비교하는 읽기 전용 RPC다. 완료 후 변경도 원래 완료 상태·판정·결과를 보존하면서 차이를 반환한다. 파일 해시가 없는 과거 결과는 비교 불가를 안내한다. M3의 주기 관측과 일반 상세 조회에 파일 감시를 추가하지 않았다. 외부 편집기의 동시 쓰기까지 원자적으로 잠그는 보장은 없다.

GUI 판정은 신규 M4 요청에만 제출했다. 새 실제 작업의 검사 파일 변화는 의도적인 주석 추가이며 단언 2개가 유지되는지 확인했다. 오류·시간 제한·예산 초과는 자동 fixture로 검증했으며 실제 모델 장애를 주입한 것으로 보고하지 않는다. M3 회귀 스크립트는 전체 리소스 수 대신 해당 TASK 제목·ID에 해당하는 Agent/Workspace가 정확히 1개인지 대조하도록 바꿔 이후 마일스톤 요청과 공존하게 했다.

마지막 검토에서 ignore 상태를 지문에 포함하는 경계를 추가했다. 첫 구현의 Git 옵션 조합 오류는 fixture에서 발견해 경로별 `check-ignore -q`로 수정했다. 수정 후 70개 전체 테스트와 실제 M4 지문 비교를 재검증했다. GUI 이후 수정은 서버의 ignore 상태 대조이며 화면·정상 파일 지문은 유지했다.

## 재현과 후속 작업

이 PC에서 보존 실행만 대조:

```powershell
npm run m4 -- verify m4-20261112-review-001
```

이 명령은 완료 JSON을 변경하지 않지만 **해당 M4 Worktree의 구현 파일에 임시 주석을 붙였다가 finally에서 복원**하여 완료 후 비교를 시험한다. 모든 세션이 멈춘 상태에서 실행한다. 이전 요청이나 검사 파일은 수정하지 않는다.

새 환경은 [README](../../README.md)의 설치·sandbox 준비를 먼저 수행한다. 새 실행 ID로 `npm run m4 -- init <id>` → `start` → `wait` → `exercise`를 실행하고 GUI에서 조건·검사 변경 사유·최종 메모를 확인하여 완료한 뒤 `verify`한다. 이미 실행한 ID로 init/exercise를 재시도하지 않는다. 중간 실패는 해당 manifest와 기존 리소스를 확인하며 새 요청으로 덮어쓰지 않는다.

M5의 초기 재시도·unknown 해결·수정 재개 흐름, M6의 장시간·성능·장애 수용 검증은 수행하지 않았다. M4에서 추가한 재검증 명령은 기존 M1~M3 유스케이스를 UI에 연결한 것이며 별도 세션을 생성하지 않는다.
