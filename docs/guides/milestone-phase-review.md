# 두 Unity 게임의 Phase 검토

각 게임을 별도 프로젝트로 등록하고 작업실의 로드맵 편집기에서 `acceptance`를 설정한다. 같은 역할 묶음을 복사해도 프로젝트 ID, 통합 브랜치, 검사 파일의 실제 내용, 결과 지문과 판정은 각 게임에 속한다. 기존 로드맵은 이 선택 항목 없이 실행할 수 있다.

## 프로젝트 설정

아래 항목은 로드맵 JSON의 일부다. Feature의 `role`과 프로젝트에 등록한 역할 이름이 일치해야 한다. 모든 역할의 `outputs`에는 허용할 정확한 경로를 쓰고 `checks`에는 고정할 Node 검사 파일을 지정한다. 같은 경로의 검사도 게임마다 다른 규칙을 검증할 수 있다. 프로젝트별 전체 예시는 [두 게임의 로컬 PoC](../../scripts/milestone-acceptance-poc.mjs)에 있다.

```json
{
  "acceptance": {
    "version": 1,
    "pipeline": "unity-level-v1",
    "roles": [
      {
        "role": "builder",
        "tool": "level",
        "outputs": ["Assets/Resources/Route.json"],
        "checks": ["checks/Level.test.cjs"]
      }
    ]
  }
}
```

`planning` 역할은 기획 요청을, `coding`, `level`, `qa`는 코딩 제작기를 사용한다. 레벨은 Unity가 직접 읽는 JSON·Scene·asset을 출력하며 실제 플레이 근거가 필요하다. `art`, `sound`, `vfx`는 D5 제작 어댑터 대기 상태로 미리보기에 표시된다. 기획·코딩 제작기에서 임의로 대체하지 않는다. 프로젝트별 필수 검사는 Feature의 자체 검사에 더해지며, 프로필을 등록한 게임에는 Unity 통합과 사람 승인이 적용된다.

## 실행과 인계

1. 작업실에서 Phase와 시작·끝 Milestone을 선택하고 미리보기를 연다. 입력 누락, 미지원 역할, 경로·정책 충돌을 수정하고 다시 확인한다.
2. 로컬 통합 브랜치를 선택한다. 같은 게임의 후속 Phase에서도 이 브랜치를 사용한다. 결과 검토와 내보내기를 마친 Feature부터 통합된다. 후속 PLAN에서 앞선 결과의 ID, 지문, 경로별 SHA-256과 형식을 확인할 수 있다.
3. 마지막 커밋에서 고정된 검사, PlayMode, Windows 빌드, Player 실행이 끝나면 작업실에서 진행 상황을 조회한다. 전체 Phase를 담은 완료 run에 플레이 검토가 열린다. 선택 구간만 완료한 경우에는 전체 Milestone을 선택해 실행한다.
4. **Phase 플레이 검토**에서 대상 커밋, 빌드 전체의 SHA-256, Player 경로를 확인한다. `Hud.exe`는 같은 폴더의 데이터와 함께 실행한다. 레벨 배치, 이동·클리어, 조작감·밸런스를 확인하고 사유를 적어 승인하거나 반려한다. 전체 파일 지문과 마지막 검사 근거를 다시 대조한 뒤 판정 이력에 추가한다.
5. 승인한 게임에서 다음 Phase의 구간을 미리 보고 실행한다. 승인 직후에도 다음 실행을 만들기 전까지 별도 작업이 시작되지 않는다. 반려 후에는 필요한 변경을 적용해 명시적으로 재실행하고 새 근거를 확인한다. 기존 실행과 결정 이력은 보존된다.

## 복구와 비용

같은 PC와 검증 홈에서 프로젝트를 다시 등록하면 기존 프로젝트 ID와 이력이 열린다. 다른 홈에서 가져온 원본의 PLAN·결과는 조회할 수 있다. 로컬 통합 저장소, 검증 원장 또는 실제 빌드가 없으면 플레이 승인을 다시 사용할 수 없다. 자동으로 미확정 세션에 새 요청을 보내지 말고, 기존 PC에서 소유 세션과 통합 SHA를 먼저 대조한다.

작업실의 소요 시간은 실행 이력의 첫 시각과 마지막 시각 사이이며 대기도 포함한다. 제작 호출은 기록된 PLAN·실행·재개 요청 수다. 실제 청구 금액은 현재 공급자 계약에서 제공하지 않는다. D6 복구에는 게임의 Git 원본·프로젝트 문서, 검증 홈의 프로젝트 레지스트리, 통합 Git, 승인·Unity 원장, Windows 빌드 전체, 세션 소유 정보가 필요하다. 새 PC의 Unity 버전·모듈·라이선스도 확인한다. 지침·검사를 수정하면 새 범위를 확인해야 한다.

`unity-level-v1`은 MA5의 `hud-win64-v1`을 확장한다. 지원 Editor 및 Scene 계약은 [MA5 검증 기록](../decisions/milestone-unity-validation.md)에 있다. Player는 같은 프로세스에서 기존 HUD 동작을 검증하고 `ORCHIVA_LEVEL_SIGNAL`에 이번 실행 nonce, 게임 이름, 실제 이동 수·수집 수·벽 충돌·클리어 결과를 기록한다. 입력 예시는 [시험 게임 보드](../../scripts/fixtures/ma6/RouteBoard.cs)에 있다.
