# 계획 규칙

## 작성과 등록

- 단계별 구현 계획은 [구현 계획 템플릿](plan-template.md)을 사용하고 [목록](README.md)에 등록한다. 문서 작업도 계획이 필요하면 같은 템플릿에서 실행 검증의 비적용 사유와 정적 검증을 기록한다.
- 현재 코드·설계·검증 기록에 근거하여 목표, 포함·제외 범위, 작업 순서, 파일, 검증과 완료 조건을 적는다. 미구현 명령·파일은 예정이라고 표시한다.
- 새 계획은 `proposed`로 등록한다. 계획 작성 완료는 구현 완료가 아니다.
- `README.md`는 실행 순서와 상태의 원본이다. 계획 본문의 상태와 목록을 같은 변경에서 갱신한다. 후속 단계 개요는 상세 계획으로 간주하지 않는다.

## 상태와 실행

| 상태 | 의미와 변경 조건 |
| --- | --- |
| `proposed` | 계획 작성됨, 구현 시작 전 |
| `active` | 사용자에게 해당 구현 범위가 허용되었고 작업 중. 대화의 실행 지시를 근거로 기록 |
| `paused` | 사용자가 명시적으로 중지를 요청함. 기존 승인·변경·검증 이력 보존 |
| `completed` | 범위 내 변경과 필수 검증·완료 조건을 모두 충족 |
| `cancelled` | 사용자 취소 또는 다른 계획으로 대체. 사유와 후속 계획 기록 |

- 동시에 하나의 계획만 `active`로 둔다. 단일 계획 내부의 작업과 통상적인 수정·검증에 매번 승인을 요구하지 않는다.
- 사용자의 기존 구현 지시로 허용된 범위를 다시 승인받지 않는다. 계획 문서만 요청한 경우에는 그 요청을 구현 승인으로 확대하지 않는다.
- `paused`는 사용자 요청으로만 설정하고, 재개 요청이 오면 이전 승인 범위에서 `active`로 돌린다.
- 일시적인 오류·의존성 미해결은 차단 사항으로 기록한다. 이를 완료나 취소로 표시하지 않는다.
- 완료 조건을 만족하지 못한 항목이 있으면 목록에 남긴다. 검증 불가를 통과로 바꾸거나 완료 직전에 조건을 근거 없이 축소하지 않는다.

## 실행 기록

구현 중 중요한 변경·결정·검증 결과를 계획에 갱신한다. 한 단계가 제품 설계에 영향을 주면 [MVP 설계](../mvp-design.md)의 관련 내용도 정합성을 맞춘다. 변경 승인·검증 이력과 현재 해야 할 일을 구분하여 다음 작업자가 이어갈 수 있게 한다.
