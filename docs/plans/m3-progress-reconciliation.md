## 목표

브라우저와 무관하게 실행 중 요청을 관측하고 종료 시 검증까지 진행한다. daemon 재시작 후 기존 ID·시도·결과·슬롯을 복원하고 안전한 준비 단계만 이어간다. 목록은 요약·필터·페이지로 조회하며 상세는 진행·결과·이력을 분리한다.

## 현재 근거와 확인할 사항

M2 시작 RPC는 외부 생성이 끝나야 응답한다. M0의 OwnedConnection은 초기 연결·해제만 소유하고 운영 재연결 루프는 없다. TrackExecution은 프로젝트→요청 잠금과 sourceKey로 중복 수집을 방지하지만 검증 재시작 중 관측 오류를 수집 실패로 오판할 수 있다. 기존6건(원래PoC4건, M2실행1건, GUI초안1건)은 백업 후 보존한다. SDK 동기 등록을 유지하며 콜백 컨텍스트를 저장하지 않는다.

## 범위

포함: 시작 접수/실행 분리, 단일 5초 관측 루프·Hook 깨우기·5/10/20/30초 재접속/관측 backoff·종료 drain, 초기 복원 gate, observation 메타데이터와 revision 분리, 미확정 생성 보존, 읽기 전용 페이지/상세·연결진단 RPC, 진행·결과·이력 탭·필터·20건 페이지·상태별 행동. 기존 list/get RPC는 회귀 호환을 유지한다.

주기 대상은 실행 슬롯 점유 요청과 아직 결과 없는 실행 요청이다. 이미 검증된 검토 대기·실패·완료는 반복 수집하지 않는다. Hook이나 명시적 상태 확인으로 외부 변화를 확인할 수 있다. 완료 후 파일 변경 표시와 조건별 판정은 M4, 초기 실패 재시도·unknown 사용자 해결은 M5, 30분 부하·성능 수용은 M6다.

실제 시험은 별도 M3 sandbox 요청1건, 추가 세션 없는 보존 실행 재관측, 시험 소유 작업의 실행 중 Plugin 재등록과 idle 로컬 daemon 정상 재시작이다. 원래4건과 M2 증거를 새 시험 입력으로 수정하지 않는다. 활성인 무관한 세션이 있으면 재시작하지 않는다. 원격 push/merge·전역 설정 변경은 없다.

## 실패 처리와 복원

시작 전 원본 바이트와 리소스 수를 백업한다. 연결 실패는 마지막 확정 상태를 유지하며 자동 실행 재시도를 하지 않는다. 새 시험만 수정하고 결과가 불확실하면 명령·슬롯을 보존한다. 종료 시 타이머 중단→소유 연결 종료/진행 작업 drain→저장소 해제 순서를 지킨다. 검증 실패는 테스트 기준 변경으로 숨기지 않는다. 로컬 daemon은 정상 실행 상태로 복원하고 시험 리소스를 증거로 남긴다.

## 결정과 후속 작업

기존 전체 list/get은 호환하고 화면용 page/detail을 추가한다. 안정된 검토 결과를 주기적으로 재검증하지 않는다. 상태별 세부 실패 분류·조건별 판정·초기 실패 재시도는 M4/M5에 넘긴다.

실제 데이터7건으로 목록·필터·상세를 확인했고 다음 페이지 경계는45건 모의 데이터로 검증했다. 실제 기록을 불필요하게 늘리지 않기 위한 검증 환경 구분이며20건 페이지 계약을 축소하지 않는다. 실제 실행 중 Plugin 재등록과 idle daemon 정상 재시작을 수행했고, 중간 생성/검증 checkpoint와 통신 backoff는 모의 경계로 기록한다. M2 검증 스크립트는 비동기 접수 대기·읽기 전용 대조·시험 소유 리소스 수 확인으로 갱신했다.
