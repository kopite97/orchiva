- 실행 근거: 사용자의 M4 상세 계획 작성·구현·검증 지시

## 목표

검토자가 선택한 결과의 조건·검사·파일·응답·로그를 확인하고 조건별 근거를 남긴 뒤 최신 결과만 완료 확정한다. 과거 결과와 판정은 불변이며 재검증은 같은 시도의 새 결과를 만든다.

## 현재 근거와 확인할 사항

M3는 61개 테스트와 실제 백그라운드 실행을 검증했다. 현재 결과는 파일 경로와 검사 통과 여부만 저장하며 전체 판정 메모만 받는다. 과거 결과는 목록만 있고 상세 선택이 없다. 기존 데이터 7건은 새로운 필드를 추정해서 채우거나 재저장하지 않는다. 새로운 필드는 선택적으로 읽되 새 판정에는 필수로 검증한다.

## 범위

조건별 충족/미충족과 검사·파일 참조 또는 수동 근거, 검사 상태 4종과 출력 잘림, 파일 해시·삭제·검사 입력, 최초 검사 해시 대비 변경, 판정 직전 지문·revision·세션 검사, 과거 결과 상세, 완료 후 명시적 현재 지문 비교를 포함한다. 기존 실행·초안·복원 구조를 재사용한다. 초기 실패 재시도와 unknown 해결은 M5, 종합 성능 수용은 M6다.

실제 연동은 새 M4 요청 한 건과 해당 Worktree에서만 수행한다. 기존 7건 원본을 백업하고 바이트 비교한다. 새 결과 생성 후 파일과 검사 파일을 편집해 오래된 판정 거부·재검증·검사 변경 확인을 검증한다. 기존 daemon의 Plugin만 유휴 상태에서 reload하며 자동 push/merge하지 않는다.

## 실패 처리와 복원

실행 슬롯이나 미확정 전달이 발견되면 새 전송을 중단하고 기존 관측으로 대조한다. 실제 검증 파일 편집은 새 Worktree의 소유 파일에 한정한다. 실패 결과를 삭제하지 않고 재검증 결과를 추가한다. 이전 완료 요청을 실패 시험에 사용하지 않는다. 완료 후 변화 시험은 해당 파일 원본을 복원하되 결과·판정을 수정하지 않는다.

## 결정과 후속 작업

새 필드는 optional로 저장해 기존 결과를 재해석하지 않는다. 과거 데이터에 없는 파일 해시·조건별 판정은 미수집으로 표시한다. 최초로 수집된 검사 입력을 기준으로 비교하며 이는 검사 정확성을 인증하지 않는다. 완료 이후 현재 비교는 명시적 읽기 전용 작업으로 수행한다.


최종 상세 결과와 재현 절차는 [M4 결과](../decisions/m4-evidence-review.md)에 기록했다. 지문 불일치 시 기존 결과를 그대로 유지하고 명시적 재검증을 요구한다. 완료 후 비교는 자동 감시가 아닌 명시적 읽기 전용 작업이다. 수집 전체 실패는 새 부분 결과 대신 기존 오류 상태를 사용한다. 임시 Git fixture에서 ignore 설정이 worktree 밖에서 바뀌는 경계도 검증했다.
