# MA2 Milestone 조율과 로컬 직렬 실행

- 상태: `completed`
- 작성일: 2026-11-26 · Asia/Seoul
- 관련 설계: [로드맵 파이프라인 검토](../design/roadmap-pipeline-review.md) · [실행 순서](README.md)
- 선행 조건: [MA1](milestone-scope.md)의 확정 범위·지침 명세, 격리된 기획/코딩용 Git 프로젝트와 기존 D3 실행부.
- 실행 근거: 사용자가 검토안에 기반한 구현 PLAN 작성을 요청했다. 2026-11-26에 MA1 다음으로 MA2 구현·격리된 로컬 PoC 수행을 승인했다.

## 목표

GitHub 없이 단건 제작과 Milestone 자동화를 같은 작업실에서 선택한다. 한 슬롯으로 여러 Feature를 끝까지 처리하고 중단 후 동일한 입력·결과·명령으로 재개한다.

## 현재 근거와 확인할 사항

[ProductionService](../../server/application/desktop/production.ts), [계획 생성기](../../server/adapters/paseo/plan-generator.ts), [제작 저장소](../../server/adapters/storage/production-store.ts), [선택 반영](../../server/application/desktop/transfers.ts)을 재사용한다. v3 내부의 REQ/TASK 두 PLAN은 Feature 하나의 기존 실행 단위다.

## 범위

로컬 run과 조율 담당, 노드별 PLAN·검사·검토, B안 선택 적용, 여러 Milestone 인계와 실행 UI를 포함한다. 실제 시험은 새 격리 home의 소형 fixture에서 소유 세션·Worktree 생성 및 해당 worker 재시작만 수행한다. 병렬·외부 게시·Unity 빌드는 후속 범위다.

## 검증 계획

첫 PoC는 Feature PLAN을 사용자가 확인한 후 실행한다. 노드가 준비되면 스크립트가 현재 선행 근거·허용 영역·승인 해시를 확인하고, 제작 에이전트는 그 안에서 구현 방법을 선택한다. 테스트 원본/목록과 검증 결과 저장 위치는 제작 쓰기 영역에서 분리한다. 이후 프로젝트가 반복 작업의 자동 승인을 선택하면 신뢰된 프로필의 경로·도구·예산·검사 버전이 모두 일치한 경우에만 적용하고 승인 경위를 남긴다. 기획·범위 변경과 필수 검사 완화는 개발자 결정과 새 PLAN 검증으로 연결한다.

## 실패 처리와 복원

손상·미지원 레코드와 소유 불명 자원은 격리해 진단한다. UI 종료와 작업 종료를 구분하고 모호한 생성·전송은 자동 재발행하지 않는다. 복구 시 수락된 제안·실행 식별자를 먼저 대조하고 세션이 실제 소실된 경우에만 근거와 별도 시도를 기록한다.
