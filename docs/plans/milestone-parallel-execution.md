## 목표

독립 Feature 두 개가 실제로 겹쳐 실행되면서도 동일 Scene·경로·통합 브랜치에 충돌하는 작업은 대기한다. 단건 및 기존 v2 사용자의 단일 실행 규칙을 보존한다.

## 현재 근거와 확인할 사항

[v2 슬롯](../../server/application/execution-slot.ts), [v3 전역 검사](../../server/application/desktop/production.ts), [계약](../../shared/contracts/feature-request.ts)에 단일 실행 가정이 있다. [소스 규칙](../agents/source-conventions.md)의 현행 MVP 제약은 유지하고 Milestone 전용 정책의 적용 범위와 테스트를 구현 시 문서화한다.

## 범위

Milestone 전용 선택 설정에서 worker 2개, Unity Editor 자원 1개까지로 시험한다. 기본값은 직렬이다. 새 ID의 격리 실행에서 실제 세션과 Worktree를 생성하며 장애 시험은 소유 worker와 예약 저장 경계에 한한다. 다중 PC 분산 실행은 제외한다.

## 실패 처리와 복원

저장소 또는 외부 worker의 소유가 불명확하면 해당 용량을 보류한다. 재개 시 프로세스·세션·journal과 예약을 대조하고 오래된 worker의 추가 쓰기를 거절한다. 장애가 계속되면 신규 병렬 배정을 끄고 기존 작업을 추적한 뒤 직렬 모드로 복귀한다.
